# 师傅派单

工作台页面：**员工 → 份额**（饼图，切周，最近两周，点一块看单子）。工具：`scripts/desk/dispatch.py`。

人数口径和工钱一样：大人 1、收费小孩 0.5、免费小孩 0，多位师傅同场平分，帮手不算。周是周一到周日。

## 谁接什么（老板 2026-10-30 定）

| 师傅 | 目标 | 能接 |
|---|---|---|
| Blu | 每周 30–40 人，**人数要排第一** | 什么单都能接，**大单尽可能给他** |
| Gary | 每周 30–40 人 | 什么单都能接 |
| John | 每周 30–40 人 | 偏新手，只比 Eason 多炒了十几台，每人分到 20 人以下（20 是暂定，老板还没给数）；不去圣地亚哥附近（圣地亚哥县 + Temecula、Murrieta、Carlsbad、Fallbrook），OC 和 IE 能去 |
| Eason | 没有目标，一周 1–2 单就行，量大时多接 | 每人分到 15 人以下（含 15，小孩算半个） |
| 易非 | 不进轮转 | 不独立出台。超过 28 人的单有空才带，当帮手，最后考虑，有没有都可以 |

## 派单顺序

1. **客人指定的师傅**先定。
2. **硬条件**：同一天开场隔不到 3 小时不派同一人（真要连台看日历排班图，问老板）；区域；Eason 的 15 人上限；答应客人几位就派几位。
3. **大单给 Blu**：全场超过 20 人，第一位先给 Blu，这一步不看两周账；Blu 这周人数还没排第一，中桌也先给他。Blu 去不了再按下一条。
4. **中桌**：超过 15 人的桌只给 Blu、Gary、John，**两周累计人数最少**的先拿，平手按 Blu → Gary → John。
5. **小桌再派**：Eason 这周还没有单，先给他 1 单；其余给这周还不到 30 的主力，也是两周累计最少的先拿；主力都到 30 了才再给 Eason。
6. **只派未来 14 天内的单**。两位师傅及以上的大单可以提前定。近两个月约 69% 的人数是开场前 14 天内才订的，派太早后面就不均了。

## 补偿怎么算

**不单独记欠账，只看上周 + 本周的累计。** 上周少的人累计低，这周自然排在前面；上周多的人自然往后。

- 只算两周，不再往前滚，老账不会越滚越大。
- 只给 Blu、Gary、John 算。Eason 和易非不补。
- 两周目标是 60–80 人，低于 60 的优先补。
- 硬条件和 Blu 排第一都比补偿优先：该补的人去不了那单，就下一单再补。
- 老板说某人那周请假，那周的少不算欠他的，别给他补。脚本不知道谁请假，要手动调。
- 总量超过目标的周（比如 11/2 周 234 人）谁都下不来，这时只看互相平不平。

## 怎么用

```bash
python scripts/desk/dispatch.py ledger --week 2026-11-16     # 两周账、撞单、未派的单
python scripts/desk/dispatch.py suggest --week 2026-11-16    # 给未派的单出建议，并存 plan 文件
python scripts/desk/dispatch.py apply <plan 文件>             # 老板说"派"之后才跑
```

`--week` 给这一周里任意一天，不给就是今天。`suggest --all` 连 14 天以外的单也出建议，只用来看，一般不派。

## 规矩

- **`suggest` 不写库，`apply` 才写。** 把建议发给老板看，他说"派"才跑 `apply`。
- `suggest` 只排未派的单，已派的单计入账但不动。要调已派的单（比如解撞单），列给老板确认，再走工作台 `assign`，一单一换。
- 派单不发短信给师傅。发备料单是另一步（日历「N 场」弹窗），老板要才发。
- 写派单一律走 `/api/admin/chefs` 的 `assign`，别直接改表：它会清空 `guest_share` 让人数重分，并记 `chef_assigned` 事件。帮手走 `assign_helpers`。
- 帮手不分人头、不拿工钱。答应了 N 位师傅的单，要有 N 个主厨，帮手不算数；老板定的例外是 Neha 11/3。
- 规则变了要同步改三处：这个文件、`scripts/desk/dispatch.py` 顶上的常量、`lib/chef-share.ts`。
